<TLDR>
- Three core skills: **modify existing code**, **create new pages/routes**, **image → code**.
- **@ mention** the exact file + say **what NOT to change** — deterministic edits.
- **Commit at every milestone**; iterate with follow-up prompts when output misses.
</TLDR>

## The three core skills

| # | Goal | What you learn |
| --- | --- | --- |
| 1 | Modify existing code | Edit files that already exist (footer links in `templates/base.html`) |
| 2 | Create new files/pages | Generate new routes, templates, pages (`/terms` + `terms.html`) |
| 3 | Multimodal | Paste a design image → Claude Code writes matching HTML/CSS |

## Task 1 — modify existing code

<CodeBlock lang="text" title="the footer-links prompt">{`Add two links to the footer in @templates/base.html:
- "Terms and Conditions"
- "Privacy Policy"
Both should be plain text links, no special styling needed for now.
Point both to "#" as placeholder hrefs since the pages don't exist yet.
Do not modify anything else on the page.`}</CodeBlock>

| Prompt part | Purpose |
| --- | --- |
| Add two links to the footer | Exact action and location |
| `@templates/base.html` | @ mention → the exact file |
| Link text names | Specifies exact link text |
| Plain text, no styling | Prevents over-engineering |
| Point both to `"#"` | Sets expectations — non-functional for now |
| Do not modify anything else | Critical constraint against unintended changes |

## The @ mention system

Type `@` + a file path and Claude Code knows exactly which file you mean.

<CodeBlock lang="text" title="@ targets in Spendly">{`@templates/base.html       -> the base HTML template
@app.py                    -> the Flask application file
@static/css/landing.css    -> a specific CSS file
@templates/landing.html    -> the landing page template`}</CodeBlock>

| Without @ mention | With @ mention |
| --- | --- |
| Guesses which file to edit | Knows exactly which file |
| May edit the wrong file | Always edits the correct file |
| Non-deterministic, risky in large projects | Deterministic, safe at any size |

<Callout type="tip">
Always use @ mentions when editing specific files — a good habit in small
projects, essential as the project grows.
</Callout>

| 3 | `landing: add privacy policy page` | `/privacy` route + template |

## Task 4 — interactive functionality

<CodeBlock lang="text" title="the YouTube-modal prompt, condensed">{`Add a modal to @templates/landing.html that opens when the user
clicks "See how it works".
Requirements:
- Opens a modal overlay with an embedded YouTube video
  (use any placeholder YouTube URL for now)
- Video playable inside the modal
- Close button OR clicking outside the modal closes it
- When the modal closes, the video must stop playing
- No page libraries -- vanilla JS only
- Do not modify any other part of the page.`}</CodeBlock>

| Requirement | Reasoning |
| --- | --- |
| Placeholder YouTube URL | Build functionality first, swap URL later |
| Playable inside modal | iframe must be sized properly |
| Close on button click | Standard UX expectation |
| Close on outside click | Clicking the dark overlay should close |
| Video stops on close | Common bug — audio keeps playing |
| Vanilla JS only | Project doesn't use React/Vue/jQuery |
| Don't modify other parts | Prevents unintended side effects |

## Common mistakes and fixes

| What happened | What Claude Code did | Fix |
| --- | --- | --- |
| Wrong CSS filename in prompt | Created a new CSS file instead of editing | Prompt: "Merge these two CSS files" |
| Forgot Bash Mode | Typed `git add .` in prompt mode | Claude handled it anyway |
| Terms page wrong styling | Page didn't match website theme | Follow-up: "Match the website's theme" |

## Best practices

| Prompt writing | Development workflow |
| --- | --- |
| Be specific about files — always @ mention | Commit after every meaningful change — precise rollbacks |
| Include constraints — say what NOT to do | Verify in the browser before committing |
| Pre-write and refine prompts, never type live | Iterate — the AI workflow is inherently iterative |
| Include styling requirements upfront | Learn from mistakes — bake known fixes into future prompts |

## In 30 seconds

- **Three skills**: edit existing, create new pages/routes, image → code.
- **Refine prompts outside** the terminal; @ mention files; forbid side effects.
- **`git commit` every milestone**; verify in the browser first.
- Bad first output is normal — **one follow-up prompt** usually fixes it.

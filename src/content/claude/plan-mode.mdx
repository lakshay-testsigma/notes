## The spec: database setup

Replace the stub in `database/db.py` with working SQLite — the data-layer
foundation every future Spendly feature depends on.

**Table A — `users`**

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | INTEGER | Primary key, autoincrement |
| `name` | TEXT | Not null |
| `email` | TEXT | Unique, not null |
| `password_hash` | TEXT | Not null |
| `created_at` | TEXT | Default `datetime('now')` |

**Table B — `expenses`**

| Column | Type | Constraints |
| --- | --- | --- |
| `id` | INTEGER | Primary key, autoincrement |
| `user_id` | INTEGER | Foreign key → `users.id`, not null |
| `amount` | REAL | Not null |
| `category` | TEXT | Not null |
| `date` | TEXT | Not null (format: YYYY-MM-DD) |
| `description` | TEXT | Nullable |
| `created_at` | TEXT | Default `datetime('now')` |

<CodeBlock lang="python" title="the three functions the spec demands">{`def get_db():
    """Open and return a database connection."""
    conn = sqlite3.connect("spendly.db")
    conn.row_factory = sqlite3.Row
    conn.execute("PRAGMA foreign_keys = ON")   # Critical!
    return conn
def init_db():
    """Create tables if they don't already exist."""
    db = get_db()
    db.execute("CREATE TABLE IF NOT EXISTS users ( ... )")     # schema per Table A
    db.execute("CREATE TABLE IF NOT EXISTS expenses ( ... )")  # schema per Table B
    db.commit()
def seed_db():
    """Insert demo data once (prevents duplicates)."""
    db = get_db()
    if db.execute("SELECT COUNT(*) FROM users").fetchone()[0] > 0:
        return                                 # exit early -- don't insert again
    from werkzeug.security import generate_password_hash
    db.execute("INSERT INTO users (name, email, password_hash) VALUES (?, ?, ?)",
               ("Demo User", "demo@spendly.com", generate_password_hash("demo123")))
    db.commit()`}</CodeBlock>

| Rule | Meaning |
| --- | --- |
| No ORMs | No SQLAlchemy — write raw SQL |
| Parameterized queries only | Never Python string formatting inside SQL |
| Foreign keys ON | Explicitly `PRAGMA foreign_keys = ON` |
| Amounts as `REAL` | Float, not INTEGER |
| Werkzeug hashing | Never store plain passwords |
| Dates `YYYY-MM-DD` | One canonical format |

<CodeBlock lang="text" title="acceptance criteria — the definition of done">{`[ ] DB file created on app startup     [ ] Both tables, correct schema + constraints
[ ] Demo user, properly hashed pwd     [ ] 8 sample expenses across categories
[ ] Re-running seed = NO duplicates    [ ] App starts without errors
[ ] Foreign key enforcement working    [ ] All queries use parameterized SQL`}</CodeBlock>

## Plan Mode — deep dive

A special operating mode: Claude Code **only reads, never writes** — a
"thinking phase" before any coding.

<Diagram caption="Agents fan out over spec + code, but the only output is a plan — writes are impossible." chart={`

  P -.-> X["writes ✗"]

<CodeBlock lang="bash" title="activate it, then prompt it">{`# Method 1: Shift+Tab (press twice)   -> "Plan Mode ON" appears
# Method 2:
/plan

# Example prompt used in Plan Mode:
Read .claude/specs/01-database-setup.md and the existing
database/db.py and app.py, then generate an implementation plan.
Save this plan to .claude/plans/01-database-setup.md`}</CodeBlock>

## Good practices

| Model | Speed · Cost | Best for |
| --- | --- | --- |
| Haiku | Fastest · low | Simple tasks, quick edits |
| Sonnet | Balanced · medium | Most everyday features |
| Opus | Slowest · high, strongest | Complex planning, large refactors |

<Callout type="tip">
Recommended workflow: **Opus for planning → Sonnet for coding**.
</Callout>

**Extended thinking** — normally Claude starts "talking" before it has fully
"thought"; this adds a whiteboard phase first.

<Diagram caption="Reason on a scratchpad first, answer second. Toggle via /config → thinking → true/false." chart={`
flowchart LR
  Q[question] --> R[["scratchpad<br/>reasoning"]] --> A[final answer]
`} />

**Effort level** — directly controls how many tokens the scratchpad phase may use.

| Effort | Token budget | Use when |
| --- | --- | --- |
| Low | ~500–1,000 | Quick, simple planning |
| Medium | Moderate | Most everyday features |
| High | Large | Complex features, many files |
| Max | Unlimited | Opus only, very complex architecture |

<CodeBlock lang="bash" title="set it — or let claude decide">{`/effort low | medium | high | max
/effort auto     # <- recommended: Claude decides automatically`}</CodeBlock>

**Ultraplan** — a superior, remote version of Plan Mode.

| Feature | Regular Plan Mode | Ultraplan |
| --- | --- | --- |
| Where it runs | Your local machine | Cloud (Anthropic's servers) |
| Model used | Whatever you've selected | Opus 4 (always) |
| Editing experience | Terminal output | Rich web editor |
| Best for | Typical features | Highly complex features |

<CodeBlock lang="bash" title="reach for it when regular plans disappoint">{`/ultraplan
# OR include the word in your prompt:
ultraplan the registration feature for this website
# use for: unsatisfying regular plans, many-file features, deep architecture, mass refactoring`}</CodeBlock>

## In 30 seconds

- **Spec first** — tables, functions, rules, acceptance criteria in `.claude/specs/`.
- **Plan Mode** (Shift+Tab ×2) reads everything, writes nothing, saves a plan to `.claude/plans/`.
- **Opus plans, Sonnet codes**; `/effort auto` for thinking budget; **Ultraplan** for the monsters.
- Implement with manual approvals, validate against acceptance criteria, then **commit → push → PR → merge → delete branch**.

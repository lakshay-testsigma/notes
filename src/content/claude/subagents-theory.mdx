<Analogy>
A subagent is a function call — you never read the 200 lines inside; you pass
input, it returns one clean output.
</Analogy>

<TLDR>
- **LLMs are stateless** — "memory" is your app resending the whole conversation, which is **catastrophic for coding**.
- A **subagent** = a specialized assistant in its **own isolated context**: heavy work in, distilled summary out, then destroyed.
- Four wins — **isolation, specialization, modularity, parallelism**; triggered **implicitly** (Claude decides) or **explicitly** (you say so).
</TLDR>

## How LLMs really work

You never talk to the model directly — every interaction is one request-response cycle through an API wrapper. No session, no persistent connection.

<Diagram caption="One request, one response — the model keeps nothing in between." chart={`
flowchart LR
  Y([you]) --> W[API wrapper] --> L[LLM]
  L -. response .-> Y
`} />

## The core truth: stateless

Anything you said yesterday — or 10 seconds ago — is gone the moment the response returns.

| Call | Question | LLM memory | Response |
| --- | --- | --- | --- |
| Call 1 | "Capital of France?" | Empty | "Paris." |
| Call 2 | "What about Germany?" | Empty | "In what context?" |

## Why the hack fails for coding

A ~30,000-token codebase, one request — "add authentication". Watch the escalation:

| Turn | What gets sent | Tokens · cost |
| --- | --- | --- |
| 1 | codebase (30k) + message | ~30,100 · ~$0.09 |
| 2 | codebase + history (2.1k) + message | ~32,200 · heavier |
| 3 | codebase + history (5k) + new code (3.5k) + message | ~39,000 · heavier |
| 8 | codebase + huge history + all generated code | ~76,100 · ~$0.23/turn |

## The two real dangers

| Danger | What happens |
| --- | --- |
| Context overflow | Oldest tokens **silently dropped** — no warning, invisible corruption |
| Lost in the middle | Attention peaks at start & end — critical files mid-context get **ignored** |

## The math behind the benefit

Without a planning subagent, every turn carries the full codebase; with one, the subagent absorbs the 30k **once** and returns a 500-token plan.

<Formula tex={"\\text{Tokens}_n = \\underbrace{30{,}000}_{\\to\\ 500} + \\text{prev\\_conv}_n + \\text{new\\_msg}_n"} caption="Per-turn cost: the 30k codebase term shrinks to a 500-token summary." />

<Formula tex={"\\Delta = 30{,}000 - 500 = 29{,}500"} caption="Tokens saved every single turn." />

| | Without subagent | With subagent |
| --- | --- | --- |
| Main context | 30,000 tokens of codebase | ~500-token summary |
| Resent | every single turn | every turn — but tiny |
| Context | fills fast | stays lean |
| Costs | explode | stay low |

| --- | --- |
| Understand the code | **Explorer** |

| Test the code | **Tester** |
| Audit for security | **Security** |

<Callout type="tip">
3 datasets, each needing EDA? Spawn **3 parallel EDA subagents** — one per

</Callout>

## Real-world use cases

| Use case | Why a subagent |
| --- | --- |
| Codebase exploration | Huge codebase never loaded into main context |
| Code review | The agent that wrote the code is biased — use a fresh one |
| Testing | The author of code is not the best person to write its tests |
| Multi-stage pipelines | Clean hand-offs: contract → implementation → test |
| Parallel independent tasks | Three services built simultaneously by 3 subagents |
| Security audits | A dedicated security-focused prompt catches more |

## Taxonomy: built-in vs custom

| Type | Scope | Examples |
| --- | --- | --- |
| Built-in | Always available | Explore, Plan, General-Purpose |
| Custom — user-level | All projects on the machine | lives in `~/.claude/` |
| Custom — project-level | This project only | lives in `.claude/` |

<CodeBlock lang="bash" title="where custom subagents live">{`~/.claude/    # user-level — every project on this machine
.claude/      # project-level — this project only`}</CodeBlock>

## The built-ins

| Built-in | Triggers when | Job |
| --- | --- | --- |
| **Explore** | You ask to explore/analyze the codebase | Reads files, returns summary |
| **Plan** | You enter Plan Mode | Reads spec, designs implementation |
| **General-Purpose** | Claude judges a task needs isolation | Handles read/write tasks |

## How they get triggered

Two modes — identical for built-in and custom subagents:

| Mode | How it works |
| --- | --- |
| **Implicit** | Claude recognizes the task needs a subagent, delegates on its own |
| **Explicit** | You tell Claude which subagent to use |

<Callout type="info">
In practice, **implicit is by far the most common** — Claude Code uses subagents
automatically for most explore/plan workflows.
</Callout>

## In 30 seconds

- Stateless model → app replays history → for coding that resend is **catastrophic**: overflow, lost-in-the-middle, ~$1.14 per feature.
- A **subagent** = isolated context, distilled return, destroyed after — **29,500 tokens saved per turn** in the example.
- **Built-in** (Explore, Plan, General-Purpose) vs **custom** (user vs project level); triggered **implicitly** (common) or **explicitly**.

<TLDR>
- **CLAUDE.md** = a **persistent system prompt** for your project — a plain Markdown file auto-loaded at every session start.
- The **.claude folder** is the config toolbox — **project-level or global** — for skills, commands, rules, sub-agents.
- **memory.md** is **auto memory**: Claude writes it itself, silently, and re-reads it next session.
</TLDR>

## What is CLAUDE.md?

A Markdown file in your project directory holding details, conventions and constraints — nothing technically fancy.

<Diagram caption="Every new session, Claude Code pulls the file automatically — consistent code without re-explaining." chart={`

## The .claude folder

A local configuration directory — how Claude behaves for one project, or for all of them.

| | Project-level | Global / user-level |
| --- | --- | --- |
| Location | `<project>/.claude/` | `~/.claude/` (home) |
| Scope | This project only | Every project on your machine |
| Shared with team | Yes (in the repo) | No (your machine only) |

<CodeBlock lang="bash" title="what's inside">{`.claude/
├── settings.local.json   # tool permissions (personal, not shared)
├── commands/             # custom slash commands
├── rules/                # split CLAUDE.md content (loaded lazily)
├── skills/               # reusable task-specific skill files
└── agents/               # sub-agent definitions`}</CodeBlock>

## The 5 types of CLAUDE.md

| File | Loaded | Shared? |
| --- | --- | --- |
| `./CLAUDE.md` (project root) | Every session | Yes — committed |
| `./.claude/CLAUDE.md` | Every session | Yes — committed |
| `./CLAUDE.local.md` (personal) | Every session | No — gitignored |
| `~/.claude/CLAUDE.md` (global) | Every session, all projects | No — personal |
| `./folder/CLAUDE.md` (subdir) | Lazy — when needed | Yes — committed |

## Good practices

| Do | Because |
| --- | --- |
| `/init`, then prune aggressively | It's a starting point — remove the noise |
| Commit it to git | Treat it as part of the codebase |
| Only universal things | Feature-specific rules don't belong here |
| Use emphasis sparingly | See the callout below |
| Keep it short — under 200 lines | More instructions → worse following; 200–300 is the ceiling |
| Treat it as a living document | Refresh after every feature; build organically |
| Correct once, then codify | Repeated mistake → add an instruction |
| Audit periodically | Weekly/monthly — old rules turn counter-productive |

<Callout type="warning">
If everything is **IMPORTANT**, nothing is. People abuse it 10–12 times per file —
reserve it for truly critical rules.
</Callout>

## When it outgrows 200 lines

| Solution | Best for | Loading |
| --- | --- | --- |
| Split into `rules/` | Topic-based separation | Lazy — when topic needed |
| `@` imports | Reusing existing docs | When file is referenced |
| Subdirectory CLAUDE.md | Multi-area projects | Lazy — when in that folder |

<CodeBlock lang="bash" title="solution 1 — split into .claude/rules/">{`.claude/rules/
├── code-style.md
├── testing.md
├── security.md
└── api-conventions.md`}</CodeBlock>

<CodeBlock lang="md" title="solution 2 — @ imports">{`## API Conventions
See @docs/api-guidelines.md

## Git Workflow
See @docs/contributing.md`}</CodeBlock>

## Auto memory

Claude's own notebook: as it works, it records learnings, patterns and insights — silently.

<CodeBlock lang="bash" title="where memory.md lives">{`~/.claude/
└── projects/
    └── <your-project-name>/
        └── memory/
            └── memory.md    # ← here!
# example content:

# - Project uses INR, not USD`}</CodeBlock>

<Callout type="warning">
Only the **top 200 lines** of memory.md load at session start — manage and prune it as it grows.
</Callout>

> Based on whatever we discussed in this session, update your memory.md`}</CodeBlock>

## The /memory command

<CodeBlock lang="bash" title="one command, three doors">{`> /memory`}</CodeBlock>

| Option | Opens |
| --- | --- |
| Project Memory | Your project's `CLAUDE.md` |
| User Memory | The home-directory `~/.claude/CLAUDE.md` |
| Open Auto Memory Folder | The `memory.md` file |

All three are memory files — the only difference is **who writes them**:

| File | Who writes it | What it is |
| --- | --- | --- |
| `CLAUDE.md` (project) | The programmer | Project-level memory |
| `CLAUDE.md` (user) | The programmer | Personal/global memory |
| `memory.md` | Claude itself | Auto-learned memory |

  C -- just me --> F[CLAUDE.local.md]

- **CLAUDE.md** = persistent system prompt; `/init` gives ~30%, you write the other 70%.
- Keep it **under 200 lines**; overflow into `.claude/rules/`, `@` imports, or subdirectory files.
- **memory.md** = Claude's auto-learned memory — top 200 lines load; `/memory` opens all three files.

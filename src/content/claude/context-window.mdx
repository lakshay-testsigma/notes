<TLDR>
- The **context window** is Claude's working memory: ~**200k tokens**, but only ~**150k usable**.
- LLMs are **stateless** — each turn re-sends the whole history, so tokens grow **quadratically**.
- The antidote is discipline: **one session per feature**, proactive **/compact**, **sub-agents** for side work.
</TLDR>

## Where context comes from

Context = all the information needed to understand something correctly — and in a real project it leaks in from everywhere.

| Source | What it contains |
| --- | --- |
| Codebase | Functions, folder structure, conventions, dependencies |
| PRD / spec | Requirements, user stories, acceptance criteria, edge cases |
| JIRA / GitHub issues | Task definitions, back-and-forth decisions in comments |
| Slack / messages | Decisions made in passing, warnings about fragile code |
| Previous AI chats | Explored approaches, decisions already made with Claude |
| Git history / PRs | Past decisions, reverted attempts, review comments |

## The window — key facts

A context window is how much a model can see and remember **at one time**, measured in tokens. It can't hold infinite context.

## The quadratic growth problem

LLMs are **stateless** — every new message ships the *entire* conversation history plus itself.

## What actually fills the 200k

Of the advertised 200k, only ~**150k is usable** — the rest is spoken for before you type a word.

| Component | Tokens | Note |
| --- | --- | --- |
| System prompt | ~6,000 (fixed) | Pre-loaded by the Claude Code team |
| Tool schemas | ~8,000 (fixed) | All tool schemas load at start |
| CLAUDE.md | Tiny, persistent | Project overview file |
| Conversation history | ~45% in long sessions | Claude's replies are the main culprit |
| Tool results | Variable | Every file read, every bash output |
| Skills + MCP schemas | Loads at startup | Custom skills and MCP tools |
| Auto-compact buffer | ~33,000 (reserved) | Pre-reserved for compaction summaries |

## Auto-compaction, explained

The built-in safety valve against overflow — helpful, but it fires on its own schedule.

  caption="What happens under the hood."

    { icon: "⚖️", label: "~75–92% hit", note: "It automatically summarises the conversation history." },

<Callout type="warning">
The catch: it's **lossy** (summaries drop detail), it triggers **mid-task**
(possibly during a critical feature), and it's **beyond your control**.
</Callout>

## The three fixes

<CodeBlock lang="bash" title="fix 1 — compact on YOUR schedule">{`/compact   # same as auto-compaction, but you pick the moment`}</CodeBlock>

<Callout type="tip">
Run `/context` periodically. At ~70–75% usage, run `/compact` **between tasks,
never mid-feature** — then review the summary with `Ctrl+O`.
</Callout>

<Diagram caption="Fix 2 — each sub-agent gets its own fresh, isolated 200k window, runs in parallel, and returns only a summary." chart={`
flowchart TD
  M[Main agent] --> A[Sub-agent A]
  M --> B[Sub-agent B]
  A -. summary .-> M
  B -. summary .-> M
`} />

<CodeBlock lang="bash" title="fix 3 — the nuclear option">{`/clear   # deletes all conversation history in the current session`}</CodeBlock>

| Method | What it does | When to use |
| --- | --- | --- |
| `/compact` | Summarises history, frees space | Proactively at ~70–75% usage |
| Sub-agent | Fresh isolated 200k for a task | Parallel / isolated / exploratory work |
| `/clear` | Deletes all history | Nuclear reset within the same session |
| New session | Completely fresh 200k | Start of each new feature |

## Terminal vs GUI

Advanced features — memory editing, hooks, sub-agent management — need the terminal.

| Access method | Verdict |
| --- | --- |
| Terminal (CLI) | Original, most powerful — full access to all features |
| VS Code extension | Convenient but limited |
| Claude Desktop app | Comfortable but restricted |
| Web interface | Limited for power users |

<Analogy>
HEAD is your finger on the map. Usually it rests on a branch name; point it straight at an old commit and you're standing in the past.
</Analogy>

<TLDR>
- `git checkout` is the **Swiss Army knife** — so overloaded that `switch` and `restore` were added.
- **HEAD → branch → last commit.** Checkout a raw hash and HEAD skips the branch: **detached HEAD**. Not a bug, not a panic.
- `git restore` un-modifies a file — **not undoable**; `--staged` un-stages it — harmless.
- `git reset` moves the branch pointer back — commits gone, files kept. `--hard` kills the changes too.
- `git revert` adds a *new* commit that undoes an old one. **Shared history → revert. Private → reset.**
</TLDR>

<Steps
  caption="One file, one round trip — edit, discard, back to the committed state."

| Command | From | Does |
| --- | --- | --- |
| `git checkout HEAD <file>` | HEAD | Discard changes in that file |
| `git checkout -- <file>` | index | Discard changes — reads the index, not HEAD |
| `git restore <file>` | index | The modern equivalent |

## restore

New-ish — most tutorials and books predate it.

<Steps
  linked={false}
  caption="Three jobs, one command — pick the option that matches the mistake."
  items={[
    { icon: "🧽", label: "Un-modify", note: "git restore app.js — back to the staged version." },
    { icon: "🕰️", label: "Other source", note: "--source HEAD~1 or a commit hash." },
    { icon: "📤", label: "Un-stage", note: "--staged removes it from the staging area." }
  ]}
/>

<CodeBlock lang="bash" title="restore">{`git restore app.js                      # discard changes — from the index
git restore --source HEAD~1 home.html   # contents from the commit before HEAD
git restore --source d8194d6 app.js     # or any commit hash
git restore --staged app.js             # added by mistake? un-stage it`}</CodeBlock>

<Callout type="warning">
`git restore <file>` is **not undoable**. Uncommitted changes in that file are gone.
</Callout>

<Callout type="tip">
Feeling confused? `git status` reminds you which command to use.
</Callout>

## reset — move the pointer back

*"OH NO! I didn't mean to make that commit here!"* — e.g. commits landed on `master` that belonged on a branch.

<CodeBlock lang="bash" title="reset">{`# history: bb43f1f → 0026739 → 39c3fdd
git reset 0026739         # rewind to a hash
git reset HEAD~2          # …or count back 2 commits
git reset --hard HEAD~1   # add --hard to drop the changes too`}</CodeBlock>

<Steps
  caption="reset rewinds the branch pointer; --hard rewinds your files with it."
  items={[
    { icon: "😱", label: "Bad commit", note: "39c3fdd touched about.html + lisa.jpg." },
    { icon: "⏮️", label: "git reset 0026739", note: "Branch pointer moves back to 0026739." },
    { icon: "🗑️", label: "Commit gone", note: "39c3fdd is off the branch." },
    { icon: "📄", label: "Files kept", note: "Edits sit unstaged in your working directory — re-commit them elsewhere." },
    { icon: "💣", label: "--hard", note: "git reset --hard 0026739 — the file changes are gone too." }
  ]}
/>

<Callout type="tip">
Reset too far? `git reflog` still has the hash for a while.
</Callout>

## revert — undo by adding

Same goal, opposite mechanic: `revert` doesn't erase, it appends.

<CodeBlock lang="bash" title="revert">{`git revert 51494a6   # new commit reversing 51494a6 — Git prompts for a message`}</CodeBlock>

<GitGraph
  caption="git revert 51494a6 creates a new commit whose content is the reverse of 51494a6."

| | `git reset` | `git revert` |
| --- | --- | --- |
| Mechanism | Moves the branch pointer backwards | Adds a new, opposite commit |
| Old commits | Eliminated | Still there |
| Commit message | None | You're prompted for one |
| History | Rewritten | Preserved |

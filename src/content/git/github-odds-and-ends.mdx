<Analogy>
Git is the engine. These are the dashboard knobs around it — who can look in, who can drive, and what the sign on the door says.
</Analogy>

<TLDR>
- **Public** repo = the whole internet can see it. **Private** = owner plus people granted access.
- Invite **collaborators** in repo settings — they get push access to your repo.
- A **README.md** in the project root is auto-rendered on the repo's home page — `.md` = **Markdown**, a light syntax for formatted text, easy to pick up.
- **Gists** = instant snippet sharing, no repo setup.
- **GitHub Pages** hosts *static* sites straight from a branch.
</TLDR>

## Public vs private repos

Visibility is a per-repo switch, not an account setting.

| | **Public** | **Private** |
| --- | --- | --- |
| Who can see | Everyone on the internet | Owner + people granted access |
| Who can push | Owner + collaborators | Owner + collaborators |
| On your public profile | Listed | Hidden |

<Callout type="warning">
**Stars, watchers and release attachments never come back.** Forks of a public repo survive on their own — GitHub re-parents the fork network. The repo — issues and PRs included — can sometimes be restored within 90 days (Settings → Repositories), and your **local clone** still has the full history.
</Callout>

  caption="A collaborator can push straight to your repo — no fork required."
  items={[

    { icon: "✉️", label: "Invite", note: "Add them by GitHub username or email." },
    { icon: "✅", label: "They accept", note: "The invite lands in their inbox / GitHub notifications." },
    { icon: "⬆️", label: "Push access", note: "They can now clone and push to your repo directly." }
  ]}
/>

<Callout type="tip">
"Can I collaborate with myself?" — yes. GitHub allows only **one free account per person**, so make a second account (paid) or a **machine account** and add it as the collaborator — or make a free **organization**, host the repo there, and add your other account as a member. Classic trick for testing a collaboration flow solo.
</Callout>

## GitHub Pages

<Steps
  caption="Push code, point GitHub at a branch, get a live website."
  items={[
    { icon: "📝", label: "Write", note: "HTML / CSS / JS in your repo." },
    { icon: "⬆️", label: "Push", note: "Push it up to GitHub." },
    { icon: "🌿", label: "Pick branch", note: "Point GitHub at the branch holding the site." },
    { icon: "🌐", label: "Live", note: "GitHub hosts and publishes the page for you." }
  ]}
/>

<Callout type="warning">
Static hosting only — **no server-side code**. No Python, Ruby or Node. Just HTML/CSS/JS.
A published Pages site is a **public URL** — never put secrets in the repo you publish.
</Callout>

| | **User site** | **Project sites** |
| --- | --- | --- |
| How many | One per GitHub account | Unlimited — one per repo |
| Good for | Portfolio, personal site | A site per project |
| Default URL | `username.github.io` | `username.github.io/repo-name` |
| Changeable | Rename your account, or a custom domain | Rename the repo, or a custom domain |

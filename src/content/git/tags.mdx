<Analogy>
A branch is a bookmark that slides forward as you read. A tag is a sticker on one
page — it stays on that page forever.
</Analogy>

<TLDR>
- A tag is a **pointer to one particular commit** — a marked moment in history.
- Think **branch reference that does NOT change**. Once created, it always refers to the same commit.
- Mostly used to mark **version releases**: `v4.1.0`, `v4.1.1`, …
- Two types: **lightweight** (just a label) and **annotated** (label + author, email, date, message).
- `git push` does **not** send tags. `git push --tags` does.
</TLDR>

<Callout type="info">
Nothing forces version numbers. `hotdog`, `pickle` and `bloobertooober` are
perfectly legal tag names — semver is a convention, not a rule.
</Callout>

## The two types

| | 🪶 lightweight | 📋 annotated |
| --- | --- | --- |
| Stores | a name → a commit | commit + author, email, date, message |
| Feels like | a sticky note | a commit message |

## Viewing tags

<CodeBlock lang="bash" title="List and filter">{`git tag                # every tag in the current repository
git tag -l "*beta*"    # only tags matching a wildcard pattern`}</CodeBlock>

## Checking out a tag

<CodeBlock lang="bash" title="See the repo as it was">{`git checkout v3.1.0    # the state of the repo at that tag`}</CodeBlock>

<Callout type="warning">
This puts you in **detached HEAD** — you're standing on a commit, not a branch.
</Callout>

## Creating tags

<CodeBlock lang="bash" title="Lightweight, annotated, and older commits">{`git tag v1.0.0                    # lightweight — tags the commit HEAD references
git tag -a v1.0.0                 # annotated — opens your editor for the message
git tag -a v1.0.0 -m "Ship it"    # ...or pass it inline, exactly like git commit
git tag -a v1.0.0 8a9f2c1         # tag an OLDER commit by its hash`}</CodeBlock>

## Reuse, delete, share

<Steps
  caption="Reusing a name is the one place Git pushes back."
  items={[
    { icon: "🔁", label: "Reuse", note: "Same name on another commit → Git yells at you. Name's taken." },
    { icon: "💪", label: "Force", note: "-f forces it through — the tag now points at the new commit." }
  ]}
/>

<CodeBlock lang="bash" title="Managing tags">{`git tag -f v1.0.0    # move an existing tag
git tag -d v1.0.0    # delete a tag — the commit itself is untouched
git push --tags      # send every tag the remote doesn't already have`}</CodeBlock>

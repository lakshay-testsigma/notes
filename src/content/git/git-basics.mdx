<Analogy>
A commit is a save in a video game — a snapshot of the whole repo in time.
</Analogy>

<TLDR>
- **Repo** = a folder Git watches, plus every nested subdirectory.
- One repo per project. As many repos on your machine as you like, each with its own history.
- **Commit** = the state of many files and folders, frozen together.
- The loop: *work on stuff* → **`git add`** → **`git commit`**.
- **`git status`** is your friend. Run it constantly.
</TLDR>

## Your first two commands

<Steps
  caption="Check before you init — status errors until a repo exists."
  items={[
    { icon: "🔍", label: "Check", note: "git status — before anything else." },
    { icon: "📦", label: "Init", note: "git init creates a hidden .git folder — that folder is the repo. Once per project, top-level." }
  ]}
/>

<CodeBlock lang="bash" title="status before there is a repo">{`❯ git status
fatal: not a git repository (or any of the parent directories): .git`}</CodeBlock>

<CodeBlock lang="bash" title="init, safely">{`git status   # verify you are NOT already inside a repo
git init     # creates .git in this folder — the repo itself`}</CodeBlock>

<Callout type="warning">
**Never `git init` inside an existing repo.** Run `git status` first to verify you aren't already in one. Made one by mistake? Locate its `.git` directory and delete it — then try again in the right folder.
</Callout>

<CodeBlock lang="bash" title="undo a mistaken init">{`rm -rf .git   # ONLY to undo a repo you created by mistake`}</CodeBlock>

## Git is now watching you

<CodeBlock lang="bash" title="untracked">{`❯ touch app.js
❯ git status
On branch main

No commits yet

Untracked files:
  (use "git add <file>..." to include in what will be committed)
	app.js

nothing added to commit but untracked files present (use "git add" to track)`}</CodeBlock>

<Callout type="info">
`On branch main` assumes `init.defaultBranch=main` — a fresh install still says `master`.
</Callout>

## git add

Staging tells Git: *"please include this change in our next commit."*

<CodeBlock lang="bash" title="stage changes">{`git add file1 file2   # specific files, separated by spaces
git add .             # stage all changes at once
git status            # verify what is staged and what is not`}</CodeBlock>

## git commit

`git commit` moves everything in the staging area into the repository, with a message summarizing that snapshot.

<CodeBlock lang="bash" title="commit staged changes">{`git commit                            # text editor pops open — overwhelming when starting out
git commit -m "Add branded navbar"    # inline message, no editor. Use this one`}</CodeBlock>

<Callout type="tip">
Writing *good* commit messages is a topic of its own — later in the course.
</Callout>
